## 2. Work completed

### Task 6.1 — Understand the Basic Git Workflow

| Git operation | What it does |
|---|---|
| Check repository status | Shows which files are modified, staged or untracked. |
| Stage selected changes | Selects files to include in the next commit. |
| Create a commit | Saves staged changes in Git history. |
| View commit history | Displays previous commits and their messages. |

**Difference between Staging and Committing:**

- Staging means selecting changes that I want to save.
- Committing means permanently recording the staged changes in Git history.
- Git helps me track changes and manage different versions of my project.

### Task 6.4 — Git Command Glossary

| Git command | Explanation |
|---|---|
| `git init` | Initialises a new Git repository. |
| `git status` | Checks the current repository status. |
| `git add` | Stages changes for a commit. |
| `git commit` | Saves staged changes in Git history. |
| `git log --oneline` | Displays a short commit history. |
| `git branch` | Lists available branches. |
| `git branch update-about` | Creates a new branch. |
| `git switch update-about` | Switches to another branch. |
| `git push` | Publishes local commits to GitHub. |
| `git pull` | Retrieves and integrates remote changes. |

## 3. Commands / tools used

- `git status`: Checks repository status.
- `git add`: Stages selected changes.
- `git commit`: Records changes.
- `git log --oneline`: Displays commit history.
- `git branch`: Lists branches.
- `git switch -c`: Creates and switches to a new branch.
- `git push -u origin update-about`: Publishes the new branch to GitHub.
- `git pull`: Retrieves remote changes.
- GitHub: Used to create and review Pull Requests.
- VS Code: Used to edit README files.
- Terminal: Used to execute Git commands.

## 4. My understanding

- Git is a version control system.
- GitHub is an online platform for hosting Git repositories.
- A repository stores project files and their history.
- Staging selects changes before committing.
- A commit records changes in Git history.
- A branch allows me to work on changes separately.
- A Pull Request allows others to review proposed changes.
- Merging combines approved changes into another branch.
- Git makes teamwork and project management easier.
